# uvm v1.2.1 Comprehensive Hardening Plan

## Goal

Implement the approved hardening design and produce fresh local evidence that
the existing command surface is correct, safe, and release-ready in source.

## Architecture

Keep the existing Bash modules and move behavior to the correct owner: config
and serialization helpers in `uvm-config.sh`, lifecycle/package delegation in
`uvm-core.sh`, and trust-aware activation in `uvm-shell-hooks.sh`. Delete unsafe
internal paths instead of preserving dual implementations.

## Tech Stack

Bash 3.2-compatible shell code, BATS, `uv`, GitHub Actions, Markdown, TOML.

## Baseline/Authority Refs

- `README.md`, `README_CN.md`
- `project_document/main.md`, `project_document/UNINSTALL.md`
- `CHANGELOG.md`
- `docs/aegis/specs/2026-08-07-v1-2-1-hardening-design.md`
- Official `uv 0.12.2` CLI and settings documentation reviewed on 2026-08-07

## Compatibility Boundary

Public 1.2.0 commands and legacy record readability remain; unsafe behavior is
not retained. Development is isolated from installed user state and remote Git.

## TDD Route

- Mode: off
- Decision: skipped

## Plan checks

- Requirement Ready Check: ready; the audit findings, approved design, and user
  authorization define scope and acceptance.
- Change Necessity: code-change; documentation alone cannot prevent invalid TOML,
  untrusted sourcing, false-success package transfer, or broken rename behavior.
- Existence Check: reuse existing config/core/shell owners; add only a trust
  registry data file and test helpers required by the security contract.
- Architecture Integrity: `uvm` coordinates; `uv` performs Python, venv, package,
  and config semantics. No fallback owner is added.
- Complexity Budget: `uvm-core.sh` and `uvm-config.sh` are near the 800-line soft
  pressure signal. Changes should extract cohesive helpers and remove duplicated
  logic; do not add another generic module.

## Tasks

### 1. Safety and serialization foundation

Files: `lib/uvm-config.sh`, `tests/uvm.bats`.

- Add reusable missing-option validation, canonical path resolution, JSON string
  escaping, semantic version comparison, and trusted-local-environment helpers.
- Replace invalid mirror output with `[[index]]`, treat
  `python-install-mirror` as a distinct user-owned setting, and validate the
  managed candidate through `uv` before install.
- Verify focused configuration, JSON, relative-path, and mirror regressions.

Repair track: configuration/serialization owns safe persisted values.
Retirement track: delete `[python-downloads] url`, raw JSON interpolation, and
relative custom-path persistence.

### 2. Core lifecycle and package operations

Files: `lib/uvm-core.sh`, `bin/uvm`, `tests/uvm.bats`.

- Route export/import/clone through `uv pip --python` and propagate failures.
- Add safe rollback for newly created clone/import destinations.
- Change rename to metadata-only behavior and preserve the environment path.
- Reject missing option values and extra delete arguments.
- Preserve configured environment roots during update and resolve releases
  deterministically.
- Verify against real unseeded `uv venv` environments.

Repair track: core coordinates operations and delegates package semantics to uv.
Retirement track: delete `python -m pip`, swallowed failures, and physical venv
move logic.

### 3. Trusted shell integration

Files: `lib/uvm-shell-hooks.sh`, `bin/uvm`, completions, `tests/uvm.bats`.

- Add `uvm trust [path]`, `uvm untrust [path]`, and `uvm trust list` using the
  config-owned trust registry.
- Auto-activate `.uvmrc` targets as before; activate local `.venv` only when its
  canonical path is trusted.
- Report untrusted candidates without sourcing them and preserve prompt-hook
  compatibility and command status as far as Bash/Zsh hooks permit.
- Verify malicious activation scripts are not executed before trust.

### 4. Installer, update, and release pipeline

Files: `install.sh`, `uninstall.sh`, `.github/workflows/ci.yml`,
`.github/workflows/release.yml`, tests.

- Send interactive prompts to stderr and emit only parseable result fields.
- Reuse existing configured `UVM_ENVS_DIR` on reinstall/self-update.
- Pin maintained GitHub Actions versions and make release checks run the same
  BATS and real-uv coverage as CI.
- Add version/document consistency checks.

### 5. Documentation and release metadata

Files: `README.md`, `README_CN.md`, `EXAMPLES.md`, `CHANGELOG.md`,
`project_document/*.md`, templates and completions.

- Document 1.2.1 commands, trust flow, distinct mirror settings, rename semantics,
  uv compatibility, and migration notes.
- Remove obsolete `fix-shell-hook.sh`, invalid TOML, and 1.1.1 claims.
- Keep release actions local-only; do not create a tag or release.

### 6. Full verification and review

- Run Bash syntax checks.
- Run focused and full BATS suites with a temporary official bats checkout.
- Run ShellCheck if locally available; otherwise rely only on explicitly cited CI
  evidence and report the local gap.
- Exercise real `uv` create/export/import/clone paths in temporary directories.
- Validate generated JSON and TOML, scan for retired references, inspect `git diff
  --check`, review the full diff, and confirm no unintended workspace changes.

## Execution Readiness View

- Intent Lock: harden the existing surface for 1.2.1; do not add unrelated features.
- Scope Fence: source, tests, CI, installer, docs, and local Aegis records only.
- Baseline Lock: approved design and current documented CLI contract.
- Owner Constraint: uv owns package/Python/config semantics; uvm owns coordination.
- Compatibility Boundary: commands and records remain readable; unsafe internals retire.
- Retirement Boundary: no duplicate pip, mirror, rename, or trust paths remain.
- Test Obligations: focused regressions, real uv integration, full BATS, syntax,
  static checks where available, docs/version and lingering-reference scans.
- Drift Rule: pause and redesign if repair requires persistent-state mutation,
  a second canonical owner, or a public breaking change beyond the approved design.
- Advisory Boundary: method-pack execution guidance only; not completion authority.

## Risks

- Bash 3.2 portability and Windows Git Bash path behavior.
- Trust-registry UX is a public addition required to close the security defect.
- Network-dependent real integration tests must distinguish product failure from
  unavailable package indexes.
- Existing v1.2.0 tag remains immutable; corrected publication should be v1.2.1.

## Retirement

Deletion class: internal and contract-carrying code retirement. Path:
`delete-first`; no persistent user state is deleted. Main-path, lingering-reference,
negative security, and cross-platform boundary checks are required before closure.
